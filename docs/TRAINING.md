# Training a dedicated Raze model

Raze reuses a frontier model today (`AnthropicBackend`) plus a post-hoc
calibrator. A dedicated fine-tuned model is the next milestone; the harness
already produces training-ready data for it.

## Dataset schema

`benchmarks/offsec_dataset.json` (generated by `build_offsec_dataset.py`). Each row:

```json
{
  "finding": {"target","topic","title","has_reproduction","state"},
  "exploitable_truth": true,
  "cwe": "CWE-79",
  "vuln_class": "xss_reflected",
  "cvss_vector": "CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N",
  "cvss_score": 6.1,
  "difficulty": "easy",
  "label_rationale": "..."
}
```

The runner/exporter read only `finding` + `exploitable_truth`; the rest is
metadata used for grounding, per-difficulty scoring, and training targets.

## Export

```bash
python benchmarks/export_dataset.py benchmarks/offsec_dataset.json \
    --format messages --out train.jsonl        # SFT-shaped
python benchmarks/export_dataset.py benchmarks/offsec_dataset.json \
    --format generic  --out train.generic.jsonl
```

Each example is built with the **same** prompt builders inference uses, so the
model trains on exactly what it will see at run time. The `messages` target is a
typed judgment grounded in the taxonomy:

```json
{"probability":1.0,"rationale":"","verdict":"exploitable","preconditions":[],
 "severity":"medium","cwe":"CWE-79","vuln_class":"xss_reflected"}
```

## How to train (SFT)

1. Grow the dataset to a real size (hundreds–thousands of labeled findings across
   all classes/difficulties). Keep the nuanced hard negatives — a model that
   fires on any signal must lose points.
2. Split train/validation/test by finding (never leak a finding across splits).
3. Supervised fine-tune a small open model (or a hosted fine-tune) on the
   `messages` JSONL: input = system+user, target = the typed judgment JSON.
4. Wrap the fine-tuned model as an `LLMBackend` `complete_fn` — nothing else in
   Raze changes.

## Honest notes

- **Probability is not trained from hard labels.** SFT targets use hard labels;
  probability *calibration* stays post-hoc (`raze.calibrator`, temperature
  scaling on a held-out set). Measure ECE before/after.
- **No model is trained yet.** This documents the pipeline and ships the data;
  results require an actual training run reported under a frozen code state (see
  `benchmarks/protocol.md`).
- **Evaluate with measured metrics** (accuracy/precision/recall/F1 + accuracy by
  difficulty), kept distinct from ECE.
